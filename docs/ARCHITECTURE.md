# 数据模型与账期规则

## 分层与数据模型

- `domain/Models.kt`：本地日期周期、精确金额、数据结构、颜色分配。
- `domain/Ledger.kt`：生成、有效值、单期覆盖、向后生效、付款、停用、分币种统计。所有页面使用 `Ledger.views / Ledger.totals`。
- `domain/BackupCodec.kt`：完整备份格式与安全校验。
- `data/`：Room、DataStore、事务型仓库与设置恢复日志。
- `ui/`：四个主页面、订阅/账单详情、原生表单、文件选择、主题和 ViewModel。

Room v1 包含以下独立表。标识、关联和生效日期是可索引的列；类型化业务字段使用 Kotlin Serialization JSON 列保存，避免复杂嵌套的 Room 转换器。数据量定位个人账本，仓库以事务读写一致快照。

| 对象 | 作用 |
|---|---|
| `subscriptions` | 稳定订阅 ID、记录起点、停用截止日、归档状态 |
| `rules` | 按日期生效的完整默认规则、周期、原始锚点、稳定账期 ID |
| `bills` | 订阅 + 账期 + 本地日期构成的稳定 ID、各字段覆盖、付款信息快照、周期替代标记 |
| `payments` | 一账单一付款记录，实际日期和最小货币单位实付金额；与应付价格独立 |
| `preference_restore` | Room 与 DataStore 之间可恢复的设置提交日志 |

DataStore 保存主题、动态配色和默认币种。标题、价格、颜色覆盖以 null 表示未覆盖；备注另有 `noteSet`，可区分未覆盖与用户明确清空。已付款时冻结有效信息；主动编辑该笔已付账单可更新快照，但不会改动付款记录。恢复默认值前会展示前后变化并确认。

完整恢复先在内存校验版本、字段、日期、金额、标识唯一性、关联、账期、快照及付款一致性，并预生成当前所需账单；全部 Room 业务数据和待恢复设置在同一事务提交。DataStore 写入若遇 IO 故障，Room 中的恢复日志即为有效设置，下次启动重试，避免跨存储崩溃导致设置丢失。SQL 写入失败会完整回滚。

## 账期与金额口径

1. 每一期从原始 `LocalDate` 锚点加 N 个日/周/月/年计算，绝不以 30/365 天替代月份和年份，不从上一期继续加算。
2. 31 日遇短月取月末，后续恢复 31 日；2 月 29 日在平年取 28 日，闰年恢复 29 日。日期不经设备时区转换。
3. 默认只生成截至下个自然月末的账单；浏览后续月份时按需生成，历史从记录起点补齐。稳定 ID 去重，反复刷新/恢复不会复制账单。
4. 到期日当天未付为“待付”，严格早于今天且未付才算“逾期”。以前月份逾期单独显示，不混入本月待付。
5. 本月应付为当月到期账单的有效应付之和；待付为其中无付款记录账单的应付之和；已付为其中有付款记录账单的**实际支付金额**之和，不按付款发生月份归属。已付与其应付差额单独显示。即：应付 = 已付账单应付 + 待付，通常不等于实际已付 + 待付。
6. 下月预计支出按下月实际到期日期累计应付，包含已预付账单的应付，不将年费除以 12。不同币种永远分别统计，无汇率折算。
7. 默认字段变更只影响生效日期及之后的未付账单；过去待付、所有已付与单期覆盖保留。周期变更替代生效日及之后原周期未付账单；旧记录在备份中保留替代标记，历史与已付款不删除。
8. 向后应用只传播本次确实修改的字段，生效日为所选未来未付账单的到期日；后续相应字段已有覆盖默认保留，只有明确选择覆盖才清除该字段的覆盖。未生成的未来账单仍按日期规则取得正确值。
9. 金额全部为 Long 最小货币单位；输入/显示使用 BigDecimal，CNY 等为 2 位，JPY/KRW 为 0 位。实付允许 0，应付必须大于 0。不使用 Float/Double 做金额运算。

## 数据库升级

初始数据库版本为 1，导出的 Room Schema 位于 `app/schemas/`。不启用 `fallbackToDestructiveMigration`。后续升级必须增加显式 `Migration(n, n+1)` 并在 Application 的 builder 注册，提交新 schema，并使用 `MigrationTestHelper` 验证保留订阅、规则、覆盖与付款。不支持的数据库版本会拒绝打开并保留原文件，不会默认清空。JSON 备份格式单独版本化，当前仅接受格式 1，不兼容版本在替换前拒绝。

## 验证与边界

详见 [验证记录](../VERIFICATION.md)，该文件记录此交付实际完成的构建、自动测试和设备验证结果。

- 无系统通知/提醒、桌面组件、汇率、加密备份、合并导入或云同步。
- 表单日期范围 1900–2199 年；自定义 N 为 1–10000。超长周期的下次扣款只预览未来 101 年。
- 导入限制 32 MiB、10000 个订阅、100000 条规则、250000 笔账单/付款；面向个人使用，事务快照写入和内存列表未针对百万条数据优化。
- 停用后被移除的未来未付单期设置不会在重新启用时自动恢复；设置停用日期和重排周期前会明确提示影响。
